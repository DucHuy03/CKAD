Lab 1.4 — Label & Annotation Drill (business domain)

Tình huống giả định: sắp release v1.2.0, cần dựng nhanh 5 Pod debug (1 cho mỗi service) để chạy readiness-check thủ công trước khi release, gắn nhãn theo từng đợt kiểm tra, sau đó cập nhật trạng thái khi xong.

Bước 1 — Bulk-create 5 Pod, mỗi Pod dùng đúng image service thật
bash
kubectl config set-context --current --namespace=lab

for svc in movie-service booking-service payment-service notification-service api-gateway; do
  kubectl run debug-$svc \
    --image=$svc:latest \
    --restart=Never \
    --labels="release=v1-2-0,component=$svc,purpose=readiness-check"
done

kubectl get pods --show-labels
Bước 2 — Query bằng label selector
bash
# Tat ca pod thuoc dot readiness-check nay
kubectl get pods -l release=v1-2-0

# Chi rieng booking-service
kubectl get pods -l component=booking-service

# Nhieu gia tri cung luc (set-based selector)
kubectl get pods -l 'component in (movie-service,booking-service,payment-service)'

# Ket hop 2 dieu kien (AND)
kubectl get pods -l 'release=v1-2-0,purpose=readiness-check'
Bước 3 — Thử update label KHÔNG dùng --overwrite (để thấy lỗi có chủ đích)
bash
kubectl label pods -l release=v1-2-0 release=v1-3-0

Kết quả mong đợi: báo lỗi kiểu overwrite is false but 'release' already has a value — k8s cố tình chặn ghi đè nhầm label đã tồn tại, đây là lý do --overwrite tồn tại như 1 bước xác nhận rõ ràng.

Bước 4 — Update đúng cách bằng --overwrite
bash
kubectl label pods -l release=v1-2-0 release=v1-3-0 --overwrite

# Xac nhan
kubectl get pods -l release=v1-3-0
kubectl get pods -l release=v1-2-0
# dong lenh tren gio phai tra ve RONG - vi label da doi het sang v1-3-0

Gắn thêm label trạng thái sau khi "kiểm tra xong":

bash
kubectl label pods -l purpose=readiness-check status=verified --overwrite
Bước 5 — Annotation (khác Label ở chỗ: không dùng để query/selector, chỉ lưu thông tin mô tả thêm)
bash
kubectl annotate pods -l component=payment-service \
  checked-by="ban" \
  note="Da smoke test thu cong truoc release v1.3.0"

# Xem annotation (label selector KHONG loc duoc theo annotation - day la khac biet quan trong)
kubectl describe pod debug-payment-service | grep -A2 Annotations
Bước 6 — Dọn dẹp bằng chính label selector (không gõ tên từng Pod)
bash
kubectl delete pods -l purpose=readiness-check
kubectl get pods -l release=v1-3-0
# phai rong
Điểm cần nhớ (hay bị hỏi ở dạng câu hỏi lý thuyết trong đề thi)
	Label	Annotation
Dùng để -l selector/query	✅ Có	❌ Không
Dùng cho Service/Deployment chọn Pod	✅ Có (bắt buộc)	❌ Không
Giới hạn giá trị	Ký tự hạn chế (63 ký tự, alphanumeric + -_.)	Tự do hơn, có thể chứa văn bản dài
Ví dụ hợp lý	app=booking-service, release=v1-3-0	note="đã test tay", checked-by="ai đó"

Chạy thử toàn bộ, báo lại đặc biệt bước 3 (lỗi không --overwrite) có đúng như dự đoán không — xong thì mình sang Lab 2.1 — Rolling Update & Rollback, áp thẳng lên movie-service thật ở movie-booking (namespace production, không phải lab).
