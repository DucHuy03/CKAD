# Lab 2.4 — Kustomize Overlay

## Bước 1 — Xem output Kustomize sinh ra (CHƯA apply, chỉ đọc)

```bash
cd k8s-kustomize

kubectl kustomize overlays/dev
```

Đọc kỹ output này — phải thấy:
- `metadata.name: dev-movie-service` (namePrefix đã áp dụng)
- `spec.replicas: 1`
- **CẢ initContainer lẫn container app** đều `image: movie-service:v1`
- `envFrom` trong Deployment tự động trỏ đúng `dev-movie-service-config` (Kustomize tự sửa tham chiếu theo namePrefix cho resource nó quản lý — không cần bạn sửa tay)
- **Riêng Secret thì KHÔNG bị đổi tên**: `secretRef` vẫn giữ nguyên `movie-service-secret` (không prefix). Lý do: Secret không nằm trong `resources:` của `base/movie-service/kustomization.yaml` (bí mật không được commit lên git theo quy ước cả project), nên Kustomize không quản lý và không đổi tên nó. Bạn phải tự tạo trước 1 Secret tên đúng `movie-service-secret` trong namespace `lab` (xem `scripts/create-lab-secrets.sh`) — namePrefix chỉ áp dụng cho resource Kustomize thực sự quản lý.

```bash
kubectl kustomize overlays/prod
```

Phải thấy `prod-movie-service`, `replicas: 3`, image `v2`.

## Bước 2 — So sánh nhanh 2 output để thấy rõ khác biệt

```bash
diff <(kubectl kustomize overlays/dev) <(kubectl kustomize overlays/prod)
```

Chỉ nên thấy khác nhau đúng những chỗ đã patch (`name`, `replicas`, `image tag`, các tham chiếu theo tên) — nếu thấy khác biệt ở chỗ khác ngoài dự kiến, có nghĩa overlay đang patch nhầm.

## Bước 3 — Apply thật cả 2 overlay (chạy song song trong CÙNG namespace `lab`)

```bash
kubectl apply -k overlays/dev
kubectl apply -k overlays/prod

kubectl get deployments -n lab -l app=movie-service
# phai thay CA "dev-movie-service" (1 replica) VA "prod-movie-service" (3 replica)
```

## Bước 4 — Đổi 1 giá trị, apply lại — xác nhận "không sửa file gốc, chỉ sửa overlay"

```bash
# Thu doi dev tu v1 sang v2 CHI BANG CACH sua 1 dong trong overlays/dev/kustomization.yaml
sed -i 's/newTag: v1/newTag: v2/' overlays/dev/kustomization.yaml

kubectl apply -k overlays/dev
kubectl rollout status deployment/dev-movie-service -n lab

# Doi lai nhu cu
sed -i 's/newTag: v2/newTag: v1/' overlays/dev/kustomization.yaml
kubectl apply -k overlays/dev
```

`base/movie-service/deployment.yaml` **không hề bị đụng vào** trong suốt quá trình này — đây chính là điểm mấu chốt bài lab: 1 bộ manifest gốc, nhiều môi trường, không trùng lặp.

## Dọn dẹp

```bash
kubectl delete -k overlays/dev
kubectl delete -k overlays/prod
```

## Câu hỏi lý thuyết hay gặp trong đề thi

- `kubectl apply -k <dir>` = build kustomize + apply trong 1 lệnh, tương đương `kubectl kustomize <dir> | kubectl apply -f -`
- `namePrefix`/`namespace` ở overlay **tự động sửa mọi tham chiếu tới resource mà kustomization đó quản lý** (Service selector vẫn khớp Pod vì cả 2 cùng qua transformer, ConfigMapRef tự cập nhật tên vì ConfigMap nằm trong `resources:`) — đây là lý do Kustomize an toàn hơn `sed` thủ công (`sed` không hiểu ngữ cảnh, dễ sửa nhầm như bug `bluegreen`→`greengreen` gặp phải ở Lab 2.2). Resource **ngoài** kustomization (như Secret không commit lên git) thì không được transformer đụng tới, tên phải khớp tay.
- Không cần cài thêm gì — `kubectl` **có Kustomize tích hợp sẵn** từ bản 1.14 trở lên
