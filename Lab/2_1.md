Bước 1 — Build 2 tag v1 và v2 (không cần thay đổi code gì thêm — dùng APP_VERSION env var để phân biệt)
bash
cd movie-booking
docker build -t movie-service:v1 ./movie-service
docker build -t movie-service:v2 ./movie-service
# (2 image y het nhau ve code - khac biet o gia tri APP_VERSION set qua env
# trong Deployment, xem Buoc 2)
Bước 2 — Cập nhật Deployment thật để dùng tag v1 + thêm env APP_VERSION
bash
kubectl set image deployment/movie-service app=movie-service:v1 -n movie-booking
kubectl set env deployment/movie-service app APP_VERSION=v1 -n movie-booking

kubectl rollout status deployment/movie-service -n movie-booking

curl http://localhost:30080/healthz
# phai thay {"status":"alive","version":"v1"}
Bước 3 — Rolling update lên v2
bash
kubectl set image deployment/movie-service app=movie-service:v2 -n movie-booking
kubectl set env deployment/movie-service app APP_VERSION=v2 -n movie-booking

# Theo doi qua trinh rolling - quan sat ReplicaSet cu giam dan, moi tang dan
kubectl rollout status deployment/movie-service -n movie-booking
kubectl get rs -n movie-booking -l app=movie-service

curl http://localhost:30080/healthz
# phai thay {"status":"alive","version":"v2"}
Bước 4 — Giả lập deployment lỗi (dùng tag không tồn tại — kịch bản hay gặp thật trong đời)
bash
kubectl set image deployment/movie-service app=movie-service:v3-typo-khong-ton-tai -n movie-booking

kubectl rollout status deployment/movie-service -n movie-booking --timeout=30s
# se TIMEOUT vi Pod moi bi ImagePullBackOff, khong bao gio Ready

kubectl get pods -n movie-booking -l app=movie-service
# thay 1 Pod cu (v2) VAN CON RUNNING binh thuong - Deployment KHONG xoa Pod
# cu cho toi khi Pod moi thuc su Ready (dung "surge" hanh vi rolling update)
Bước 5 — Rollback
bash
kubectl rollout history deployment/movie-service -n movie-booking

kubectl rollout undo deployment/movie-service -n movie-booking
kubectl rollout status deployment/movie-service -n movie-booking

curl http://localhost:30080/healthz
# phai thay lai {"status":"alive","version":"v2"} - v3-typo khong bao gio duoc apply that su

Hoặc rollback về đúng revision cụ thể (không phải "về ngay trước đó"):

bash
kubectl rollout undo deployment/movie-service -n movie-booking --to-revision=1
Điểm quan trọng rút ra được từ Bước 4

Deployment không bao giờ để hệ thống rơi vào trạng thái tệ hơn hiện tại trong lúc rolling update — Pod cũ chỉ bị xoá sau khi Pod mới Ready. Đây là lý do readinessProbe bạn đã viết từ Phase 1 (/ready check DB) quan trọng sống còn ở đây: nếu thiếu readinessProbe, k8s coi Pod mới "Ready ngay khi Running" dù app bên trong còn treo, sẽ xoá Pod cũ quá sớm → downtime thật.
