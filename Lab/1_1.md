Bước 1 — Đảm bảo đang ở namespace lab
bash
kubectl config set-context --current --namespace=lab
Bước 2 — Generate YAML bằng --dry-run=client
bash
kubectl run movie-catalog-debug \
  --image=movie-service:latest \
  --restart=Never \
  --labels=app=movie-catalog-debug,component=movie-service,tier=diagnostics \
  --env=DB_HOST=postgres-movie.movie-booking.svc.cluster.local \
  --env=DB_PORT=5432 \
  --env=DB_NAME=movie_service \
  --requests=cpu=50m,memory=64Mi \
  --limits=cpu=250m,memory=256Mi \
  --dry-run=client -o yaml > labs/lab-1.1/manifests/debug-pod.yaml

Lưu ý: DB_HOST dùng FQDN đầy đủ postgres-movie.movie-booking.svc.cluster.local (không chỉ postgres-movie) — vì Pod debug này nằm ở namespace lab, khác namespace với postgres-movie (ở movie-booking). Đây chính là điểm khác biệt quan trọng so với các Pod thật trong movie-booking (chúng ở cùng namespace nên chỉ cần gọi tên ngắn postgres-movie).

bash
cat labs/lab-1.1/manifests/debug-pod.yaml
Bước 3 — Áp dụng
bash
kubectl apply -f labs/lab-1.1/manifests/debug-pod.yaml

Pod này sẽ chạy ở mode server mặc định (không có DB_PASSWORD nên db.Connect() build DSN thiếu password — Pod vẫn Running vì sql.Open() không thực sự connect ngay, chỉ khi có traffic gọi /ready mới thấy lỗi auth — đúng ý đồ bài tập: Pod Running không có nghĩa là mọi thứ bên trong nó đều đúng).

Bước 4 — Verify KHÔNG MỞ EDITOR
bash
kubectl get pod movie-catalog-debug -o wide
kubectl get pod movie-catalog-debug --show-labels
kubectl get pod movie-catalog-debug -o jsonpath='{.spec.containers[0].env}'
kubectl get pod movie-catalog-debug -o jsonpath='{.spec.containers[0].resources}'
kubectl get pod movie-catalog-debug -o jsonpath='{.status.phase}'
Bước 5 — Thử đúng ý đồ "chẩn đoán" (phần mở rộng, gắn business domain)
