Lab 3.1 — ConfigMap & Secret Injection (business domain)

Đã có sẵn phần inject qua env var (envFrom) từ Phase 4 — lab này bổ sung phần còn thiếu: Secret tạo từ file + ConfigMap mount dạng volume (khác hẳn cơ chế env var), và điểm quan trọng nhất: volume ConfigMap tự cập nhật khi sửa, env var thì không.

Kịch bản thật: movie-service cần 1 bộ "feature flags" (bật/tắt banner khuyến mãi, giới hạn số ghế hold tối đa/user...) — muốn đổi được mà không phải restart Pod, nên mount ConfigMap dạng volume thay vì env var.

Bước 1 — Tạo Secret từ file
bash
kubectl config set-context --current --namespace=lab

echo -n "postgres123" > db-password.txt
kubectl create secret generic movie-service-db-secret \
  --from-file=DB_PASSWORD=db-password.txt

rm db-password.txt   # xoa file tam ngay sau khi tao Secret - khong de lai plaintext tren disk

kubectl get secret movie-service-db-secret -o jsonpath='{.data.DB_PASSWORD}' | base64 -d
# phai in ra "postgres123"
Bước 2 — Tạo ConfigMap từ literal
bash
kubectl create configmap movie-service-feature-flags \
  --from-literal=ENABLE_PROMO_BANNER=true \
  --from-literal=MAX_HOLD_SEATS_PER_USER=6 \
  --from-literal=MAINTENANCE_MODE=false

kubectl get configmap movie-service-feature-flags -o yaml
Bước 3 — Build Pod dùng cả 2 (checklist, tự sửa từ --dry-run)
bash
kubectl run movie-service-flags-demo \
  --image=movie-service:latest \
  --restart=Never \
  --dry-run=client -o yaml > labs/lab-3.1/manifests/config-secret-pod.yaml

Checklist cần thêm:

 env (không phải envFrom) — lấy DB_PASSWORD từ Secret bằng valueFrom.secretKeyRef (cách inject từng key riêng lẻ, khác envFrom lấy nguyên cả Secret)
 volumeMounts: mount feature-flags-volume vào /etc/movie-service/feature-flags (read-only)
 volumes: 1 phần tử lấy từ configMap, tên movie-service-feature-flags
Created a file, ran a command, read a file
Created a file, ran a command, read a file
Bước 4 — Apply và verify volume mount
bash
kubectl apply -f labs/lab-3.1/manifests/config-secret-pod.yaml
kubectl wait --for=condition=Ready pod/movie-service-flags-demo --timeout=30s

# Xem ConfigMap duoc mount thanh CAC FILE RIENG BIET, moi key = 1 file
kubectl exec movie-service-flags-demo -- ls -la /etc/movie-service/feature-flags

kubectl exec movie-service-flags-demo -- cat /etc/movie-service/feature-flags/MAX_HOLD_SEATS_PER_USER
# phai in ra "6"

# Verify Secret vao dung env var
kubectl exec movie-service-flags-demo -- env | grep DB_PASSWORD
Bước 5 — Điểm quan trọng nhất bài lab: đổi ConfigMap, xem file tự cập nhật KHÔNG cần restart Pod
bash
kubectl patch configmap movie-service-feature-flags \
  -p '{"data":{"MAX_HOLD_SEATS_PER_USER":"10"}}'

# Doi ~30-60s (chu ky sync mac dinh cua kubelet), roi xem lai - KHONG restart Pod
sleep 60
kubectl exec movie-service-flags-demo -- cat /etc/movie-service/feature-flags/MAX_HOLD_SEATS_PER_USER
# phai in ra "10" - file TU DONG doi, Pod van la Pod cu tu dau, khong bi tao lai

So sánh ngược lại với Secret (env var) — không tự cập nhật:

bash
kubectl patch secret movie-service-db-secret \
  -p "{\"data\":{\"DB_PASSWORD\":\"$(echo -n 'newpassword' | base64)\"}}"

kubectl exec movie-service-flags-demo -- env | grep DB_PASSWORD
# VAN la gia tri CU - env var CHI duoc doc 1 LAN LUC container start,
# doi Secret sau do KHONG anh huong Pod dang chay, phai restart Pod (xoa
# tao lai, hoac "kubectl rollout restart" neu la Deployment) moi ap dung
Dọn dẹp
bash
kubectl delete pod movie-service-flags-demo
kubectl delete configmap movie-service-feature-flags
kubectl delete secret movie-service-db-secret
Bảng ghi nhớ (hay ra trong đề thi dạng câu hỏi lý thuyết)
	Env var (envFrom/valueFrom)	Volume mount
Cập nhật khi ConfigMap/Secret đổi	❌ Cần restart Pod	✅ Tự động (~60s), không cần restart
Phù hợp với	Config ít đổi, đơn giản	Config hay thay đổi runtime (feature flag, cert xoay vòng...)
Cách đọc trong app	os.Getenv()	Đọc file trên đĩa

Chạy thử, báo lại đặc biệt Bước 5 (file có tự cập nhật sau 60s không) — đây là phần dễ gây bất ngờ nhất nếu bạn chưa từng thấy tận mắt. Xong mình sang Lab 3.2 — Security Context Lockdown.
